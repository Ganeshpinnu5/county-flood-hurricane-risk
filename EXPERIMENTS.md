## What each run was for

### `20261103T040430Z-run-colab`

First full-panel run, on a Colab T4. Produced the V1 dashboard numbers. Superseded: its label window counted an event as positive on the day it was recorded rather than the day it began.

### `20261104T015759Z-run`

First run on the corrected label. Discarded, not published: it was warm-started from the previous feature set, so its boosters inherited rounds fitted against the old label and the run cannot be reproduced from its own directory.

### `20261106T012030Z-run`

Cold run on the corrected label. This is the run every published figure comes from. Known defects, all disclosed: five forward-rain features describe weather after the prediction date, the splits carry no embargo so the 2014 tail holds 2015 answers, and the tree is dirty at fe68bcc9.

Its lead-sweep APs match the discarded run's to five decimals, which looks like a copied file and is not one. The pooled target comes from the panel and did change between the two; the lead targets are derived inside `pipeline.py` by shifting `{hazard}_onset`, which did not. No per-lead checkpoint existed yet either, so the lead models were cold in both runs. Same seed, same labels, and test-period features that differ by about 1e-7 put them in the same place. The fits are real: `fit_seconds` is 148 against 263. Checked separately, the pooled `y_flood` column and the OR of its three derived lead targets agree on 99.998% of rows, the exceptions being county and panel edges where the shift has nothing to read.

### `20261107T202150Z-run`

Abandoned mid-run, kept only as the record that it happened. It was splitting the storm label into 50-kt and 64-kt tiers, which its `deviation_storm50` and `deviation_storm64` files are the remains of. The tiers were reverted: they cut the positive count per tier to the point where the test AP was driven by a handful of episodes. No headline, no models, nothing published from it.

### `20261108T044448Z-cyc`

The first complete cyclone-feature run, and numerically identical to the published run below -- same seed, same panel, same features. It is superseded for a mechanical reason only: it was written under CRISK_TAG=cyc, and `v2_models`, `export_v2` and `make_report` hardcode the `_run` filename suffix in about twenty places, so no downstream tool can read it. Kept because two independent invocations agreeing to five decimals is worth more than the disk it costs.

### `20261108T050140Z-run`

The published run. Cold on 44 features: the 21-column cyclone block built from the NHC a-deck forecast as it was issued, and the three CDC SVI themes removed. Hurricane AP goes from 0.15570 to 0.53294, which is 1.63x to 5.59x over the best single feature; flood barely moves, 0.26136 to 0.26190.

Read the hurricane gain with care. `cyc_in34` is NHC's *forecast* 34-kt wind radius and `y_storm` comes from HURDAT2's *best-track* 34-kt field, so part of that 5.59x is NHC's own forecast skill re-expressed rather than skill this model added. The ablation puts the cyclone block at +242% on hurricane and essentially nil on flood, so what the block buys is almost entirely the hazard it describes.

Inherited defects, unchanged: the five forward-rain features still describe rain falling after the prediction date, and the tree is dirty at 5c356632. No transformer -- both pooled TFTs still need a GPU rerun against this panel, so every transformer figure is marked withdrawn rather than carried across two feature sets.

One provenance repair came out of this run. `refdata/cone_radii.json` had never been written to disk, so `cyclone_features.cone_radii` re-measured the track-error table on every panel build and the cone margins were reproducible only because that measurement happens to be deterministic. The table is now frozen, and it was verified first: five of its seven knots appear verbatim in the panel, and the panel's minimum cone radius of 149.043949 km is exactly the interpolation of the other two at tau 30h, the shortest lead a 1-3 day window reaches.

The first HPC run, and the current published pin. Slurm job 1568242 on CREST (crest-g002, one H100 NVL), 23h05m wall, cold on the sha-verified Nov 7 panel with the full 44-feature set, 3-day embargo, storm labels capped at 2024. XGBoost and TFT trained in the same sealed run, honest git commit b5a23ed3, dirty=false.

Every lead beats its best single-feature baseline by 1.20x to 2.78x.

Numbers differ from the Colab parent at the third decimal (xgboost 3.2.0 vs 3.4.1, different hardware); every booster was re-verified to reproduce its recorded AP from the run directory alone.
